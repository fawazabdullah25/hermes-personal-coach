# coach setup — Onboarding, part 2 (steps 4–6)

ONE question per message. Save after every step.

## Step 4 — One goal, a few habits, hard dates
1. GOAL: "What is the ONE outcome you most want in the next 4–12 weeks?"
   Write it as `### O1` in GOALS.md §2. (Long-term vision, more objectives:
   later, with `coach plan`.)
2. Ask: "How many weeks for this sprint (4–12)?" Write the sprint dates
   (start TODAY; end from the terminal `date`).
3. WHY: "Why does this matter to you now? One or two sentences." Write it
   in GOALS.md §4 as `- Why O1: …` in the user's own words.
4. KEY RESULT: propose ONE in this shape: "KR 1.1: [Increase|Reduce|
   Complete] <metric> from <baseline> to <target> by <sprint end>." Ask:
   "`accept`, or send your version in the same shape." Then "Another key
   result? `yes`/`no`" (max 3). Write each with `| Status: on-track`.
5. HABITS: "Which 1–3 daily or weekly actions would move this most? One per
   line. (Three is plenty to start; more can be added later.)" For EACH:
   "H<n> <habit>: (a) how often — `Daily`, `Weekdays`, `Weekends`, or days
   like `Mon/Wed/Fri`; (b) trigger — 'After ___, I will ___'; (c) the
   2-minute version for hard days. Reply as three lines."
   Write GOALS.md §3 `H<n>: … | Frequency | Trigger | Micro`.
6. Ask: "Prefer `streaks` (I show running streaks) or `minimum` (one small
   daily minimum, no numbers)? Streaks motivate some people and weigh on
   others." Store Tracking Style.
7. DATES: "Any fixed dates in the next month — exams, deadlines, events?
   One per line with the date, or `none`." For each → work out the date
   from CLOCK, echo it back, then `protocols.md` §Commit-Add.
8. Ask: "Anything I must respect — health limits, family time, days off?"
   Write GOALS.md §4. WRITE GOALS.md; `protocols.md` §Rebuild.
   Onboarding Step = 5.

## Step 5 — How I work with you
1. DEPTH: "Two coaching levels. `core`: short scripted check-ins — best for
   small local models. `deep`: I also notice patterns, challenge excuses and
   run longer sessions — best for large hosted models. Which?" If you are a
   large hosted model, recommend `deep`; if unsure, recommend `core`.
2. ACTIONS: "Sometimes I'll suggest connecting something (calendar, voice,
   calls). When that needs installing or configuring, should I
   1 do it myself — I show each step and wait for your `yes`
   2 guide you — I write exact steps and you run them (pick this if I run
     in a sandbox and can't reach my own config)
   Reply 1 or 2." Store Action Mode: do | guide.
3. Ask: "Do you mostly type, or send voice notes?" Store Input Mode: text |
   voice.
4. Append to CONTRACT.md Agreements: `[TODAY] Chosen: <intensity>, <voice>,
   <style>.` Leave the two default agreements (rest, candour) in place and
   tell the user in one line that they exist and can be changed with
   `coach contract`.
5. WRITE config; Onboarding Step = 6.

## Step 6 — Register and start
1. cron-engine.md §Register, then §Verify.
2. `Action Mode: do` and the `memory` tool exists → ask: "May I save one
   line in your agent memory so I recognise your replies after a session
   reset? `yes`/`no`." `yes` → `integrations.md` §Memory pointer.
3. WRITE config: Version: 2.0.0; Status: active; Onboarding Step: done.
   WRITE STATE Pending: none.
4. Reply (archetype tone, ≤ 110 words): the cadence and times, the first
   check-in (name + time), and that an unanswered check-in gets <intensity
   behaviour in 8 words>. Then ONE tiny start: `protocols.md` §Tiny-Step for
   O1, phrased as an offer, not a question. Last line: "`/personal-coach
   help` lists commands; `coach integrations` connects calendar, voice or
   calls."
